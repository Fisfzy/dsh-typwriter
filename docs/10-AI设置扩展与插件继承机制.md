## 一、你要的四项，全部落地并验证

### ① 代理工作区策略（新增设置）
偏好设置 › AI 助手 › **代理工作区**：
```
论文助手读写哪个文件夹；会话也按这个目录归档。
   [论文文件夹]  [自定义目录]
```
- 选「论文文件夹」= 默认，代理 cwd = 当前打开的那篇论文 → 会话也归档在 `sessions/--<论文路径>--/`
- 选「自定义目录」→ 下面出现路径输入框

宿主侧读取顺序（`src/host/index.js`）：
```
agentWorkspaceMode === 'custom' && agentWorkspacePath  → 用它
否则                                                    → activeRoot（当前论文）
```

### ② 偏好设置移到左侧、返回 DSH 移到右侧（已验证）
实测 iframe 内标题栏文本顺序：
```
偏好设置   文件  编辑  视图  插入  格式  拼写检查  终端  帮助   布局   返回 DSH
```
- **偏好设置**：移到菜单最左侧（原来是「文件 › 偏好设置…」里的一项），点了直接开设置面板
- **返回 DSH**：移到右侧（挨着「布局」），不再挤在左边
- 两者都只在 iframe 内显示（顶层直接打开时不出现）

### ③ 是否继承宿主插件（新增开关）
偏好设置 › AI 助手 › **继承宿主插件**：
```
开着：论文助手复用本机 DSH 的插件与登录态（启动约 9 秒）。
关掉：用独立的 DSH 家目录，插件更干净、启动更快，但需要在那个家目录里有 API key。
```

## 二、为了让"继承插件"这个开关是真的，我做了一次机制验证（结论重要）

### 验证 1：能不能在 profile 里禁掉全局注入的插件？——**不行**
在 `~/.dsh/profiles/acp/cordis.patch.yml` 写入：
```yaml
- id: dsh-model-follow
  disabled: true
```
然后跑 `dsh --profile acp`：**`[dsh-model-follow] active` 照样打印，4 个 failed to import 也照样出现。**

→ 用户级 `~/.dsh/cordis.patch.yml` 是**最后应用**的一层，profile patch 覆盖不了它。
**结论：靠 profile 收窄插件集合，此路不通。**（已把该测试改动回滚）

### 验证 2：换 `DSH_HOME` 行不行？——**可行，而且快很多**
把 `DSH_HOME` 指向一个新目录再跑 `dsh --profile acp`：

| 指标 | 主 home（继承全局 patch） | 独立 home（干净） |
|---|---|---|
| `initialize` 响应 | **6,798 ms** | **2,868 ms** |
| `session/new` 完成 | 8,833 ms | 2,927 ms |
| 插件告警 | 4 项 failed to import | **零** |
| 会话落在哪 | 主 `sessions/`（按 cwd 分组） | **该 home 自己的 `sessions/`** |

→ **独立 `DSH_HOME` 同时解决三件事：插件干净、启动快 3 倍、会话彻底隔离。**

### 但是有个硬前提：**认证**
独立 home 里会话能建，但一提问就报：
```
llm-deepseek: no API key for provider route "deepseek-official";
store DEEPSEEK_API_KEY through the credentials service, or export it in the launching environment
```
我复制了 `~/.dsh/.credentials.yaml` 和 `config.yaml` 过去，**仍不够**（凭据不是明文可搬的）。

所以：
- 默认**保持继承**（`agentInheritHostPlugins !== false`），当前行为不变、可用；
- 关掉继承时要解决凭据：要么在那个 home 里重新登录一次 DSH，要么启动时把 `DEEPSEEK_API_KEY` 注入子进程环境。
  （后者最简单：插件宿主里若有该环境变量，就 `env: { DSH_HOME: ..., DEEPSEEK_API_KEY: process.env.DEEPSEEK_API_KEY }`。）

## 三、当前设置键一览（都在 `$DSH_HOME/typwriter/state.json` 的 settings 里）

| 键 | 类型 | 作用 |
|---|---|---|
| `agentPanel` | `'dsh'` | 底部/侧边用哪个代理 |
| `refineAgents` | `['dsh']` | 润色用哪个代理 |
| `agentWorkspaceMode` | `'paper' \| 'custom'` | 工作区策略，默认 `'paper'` |
| `agentWorkspacePath` | string | 自定义工作区目录 |
| `agentInheritHostPlugins` | boolean | 是否继承宿主插件，默认 true |
| `agentPresetName` / `agentPresetSkills` / `agentPresetPlugins` | string | 预设（暂未消费） |

## 四、下一步建议

1. **凭据打通**（若要用独立 home）：启动子进程时透传 `DEEPSEEK_API_KEY`；没有就退回继承并在面板提示。
2. **空闲预热**：论文一打开就后台起 ACP，面板点开即用（把 9 秒或 3 秒的等待藏掉）。
3. **消费预设**：把 `agentPresetSkills` / `agentPresetPlugins` 接进 `session/new` 与 profile 选择。
