### 关键取舍：润色不走 `headless`，走临时 ACP 会话
原计划用 `dsh --profile headless "<task>"`（一句话任务、文本输出）。实测两个问题：
1. **这个版本只认命令行参数，不读 stdin**（喂 stdin 会报 `a task is required`）；
2. 更致命：`headless` profile 在你的机器上**直接起不来**——
   `plugin tree failed to load: loader entries failed to apply`，
   原因是用户级 `~/.dsh/cordis.patch.yml` 注入的插件在 headless 里失败即致命。

所以改成：**起一个临时 ACP 会话**（复用已验证的 `src/host/acp.js`），把
`system + request` 作为一条 prompt 发过去，收集 `agent_message_chunk` 的文本，收完 `close()`。

好处：
- 不碰你现有的 profile 装配；
- 与 Agent 面板共用同一套已验证代码，行为一致；
- 临时会话独立，**不会污染面板里的对话历史**。

### 改了什么（3 处，尽量少动原结构）
| 文件 | 改动 |
|---|---|
| `lib/workspace/terminalDockState.svelte.ts` | 加 `agentRequest` 状态 + `openAgent()`：`show()` 打开面板并置请求位 |
| `views/workspace/WorkspaceMain.svelte` | 一个 `$effect` 监听 `termDock.agentRequest` → `dockView = 'agent'` 并清位 |
| `views/workspace/titlebar/LayoutMenu.svelte` | 加 `Bot` 图标项「代理对话」；显示条件 `!panelTabOff() && !!acpBridge()` |

刻意**没有**去改 `BottomDock` 的 `view` 模型（那是 `$bindable` 传下来的），
用"请求位 + 父级对齐"的方式接入，改动面最小，也不影响终端/问题/批注三个原有标签。

> 顺带澄清上一轮的疑点：Agent 标签此前"没出现"，是因为 **dock 本身没打开**（我看到的是菜单栏的「终端」按钮），
