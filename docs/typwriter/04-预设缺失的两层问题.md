# 补记：为什么"预设里没有 DeepSeek Harness"

日期：2026-11-08 · 对应截图：偏好设置 › AI 助手

## 一、截图反映的是两层问题，不只一层

### 第一层（表面）：预设清单里硬编码了 5 个 agent

`apps/texpile-editor/src/lib/ai/agentPanel/agentNames.ts`：
```ts
export const PANEL_PRESETS: PresetPanelAgent[] = ['codex', 'claude', 'opencode', 'copilot', 'gemini'];
export function agentLabel(agent: string) {
  switch (agent) { case 'codex': … case 'gemini': … default: return m.agent_panel_agent_custom(); }
}
```
`AgentPanelPrefs.svelte` 渲染的就是 `[...PANEL_PRESETS, 'custom']`。所以清单里只有那 5 个 + "自定义代理"。
（截图里"自定义代理"已勾选，说明我们上一轮写的 `agentPanel=custom` 是生效的。）

**另一处也没有 DSH**：上面的"润色所用代理"来自 `PrefsAiPanel.svelte:38-45` 的 `AGENTS = ['claude','codex','agy','custom','']`，
那是另一套契约（`agent:run`：把 prompt 喂 stdin、读文本输出），不是 ACP。

### 第二层（根本，也是真正卡住的地方）：我们的 web 宿主里根本没有 ACP 运行时

Agent 面板不是直接 spawn 进程，它走的是 preload 暴露的 `window.texpileAcp`
（`electron/src/preload.ts:549-573`，8 个方法 + `onEvent`）：

```
detect() / start() / prompt(blocks) / cancel() / answer(id, optionId)
setConfig(configId, value) / chats() / openChat(id) / close() / onEvent(cb)
```

而我们的 shim 里目前是：
```js
window.texpileAcp = undefined;
```

`acpBridge()` 拿不到这个对象 → **面板无论选哪个 agent 都启动不了**。

> 所以：**只把 "DeepSeek Harness" 加进预设清单，会得到一个能点但点了就报错的假选项。**
> 名字是表面，ACP 宿主才是根本。

## 二、要做成"真选项"需要什么

### A. 渲染端补预设（小，5 处）
| 文件 | 改动 |
|---|---|
| `ai/agentPanel/agentPanel.types.ts` | `PanelAgent` 加 `'dsh'`（`PresetPanelAgent` 自动跟随） |
| `ai/agentPanel/agentNames.ts` | `PANEL_PRESETS` 加 `'dsh'`；`agentLabel` 加 `case 'dsh': return 'DeepSeek Harness'`；`signInCommand` 加一行 |
| （可选）i18n | 若想走 `m.*`，要补 5 个语言的 key；直接返回字面量最省 |

加完 TS 联合类型会强制我们改所有 `switch (agent)` 的穷尽分支——正好把漏改的地方暴露出来。

### B. 宿主实现 `texpileAcp`（主要工作量）
在 `src/host/acp.js` 里做 **ACP 客户端**，驱动 `dsh --profile acp`：

| 方法 | 实现 |
|---|---|
| `detect` | 探测 `dsh` 是否在 PATH → `{dsh:true, codex:false, …}` |
| `start` | spawn（经 `acp-filter.mjs` 清洗 stdout）→ `initialize` → `session/new {cwd, mcpServers:[]}` → 推 `{type:'state',state:'ready'}` |
| `prompt` | 把 Texpile 的 blocks 转成 ACP content blocks → `session/prompt` → 把 `session/update` 通知转成 `{type:'update',update}` → 收尾返回 `{ok,stopReason,changes}` |
| `answer` | 回应 ACP 的 `session/request_permission` 请求；同时把待决请求推成 `{type:'permission',…}` 给面板 |
| `cancel` / `close` / `setConfig` / `chats` / `openChat` | `session/cancel`、`session/close`、`session/set_config_option`、`session/list`、`session/resume` |

事件契约照抄 `ai/agentPanel/agentPanel.types.ts` 的 `AcpEvent` 联合类型：
`{type:'state'|'update'|'permission'|'permission-done'}`，走 SSE 通道 `acp:event`。

**协议已实测可用**：`dsh --profile acp` 的 `initialize` 返回
`{"agentInfo":{"name":"deepseek-harness-acp","version":"0.0.1"},"agentCapabilities":{…}}`，
说明标准 ACP v1 surface 齐全，不需要任何私有方法。

### C. 工作区对齐
ACP 的 `session/new` 要传**绝对 cwd**——正好用我们宿主已知的论文目录（`state.json` 的 `activeRoot`）。
这样 DSH 会话的工具上下文天然就是这篇论文，不需要额外配置。

## 三、工期判断

| 部分 | 估计 |
|---|---|
| A 渲染端补预设 + 重建 bundle（2 min 构建） | 0.5 天 |
| B ACP 宿主（含事件映射、权限往返、变更清单） | 0.5~1 天 |
| C 联调（面板里真实跑一轮 prompt，修事件形状偏差） | 0.5 天 |
| **合计** | **约 1.5~2 天** |

> 提示：事件映射是最容易返工的地方——`acpSession.ts`（Electron 侧，11 KB）把 ACP 原始 update 加工成了
> 面板要的形状。我们是"照契约重写"，不是"复制"，所以第一轮要按 `AgentStepRow` / `AgentMessage` 的读法逐项对。

## 四、另一条路（供权衡）

如果目标只是"让 DSH 能写论文"，其实可以**不修面板**：按上一份报告的路线 1~2，
把论文能力注册成 DSH 的 `typst_*` 工具 + 选区上报，人在 DSH 主对话里用。
那条路不碰 `texpileAcp`，但对"在编辑器里边改边问"的体验要差一些。
